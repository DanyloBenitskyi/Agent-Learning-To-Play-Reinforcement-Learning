# Reinforcement Learning Agents

Two agents that learn to play simple games through trial and error — no
labeled training data, no pretrained models. They start out acting
randomly and get better purely from rewards and penalties received while
playing.

- **Q-learning** (tabular) — learns to solve FrozenLake, a grid-world
  navigation game
- **DQN** (Deep Q-Network) — learns to solve CartPole, a classic
  balancing task, using a small neural network

## How reinforcement learning works (quick overview)

Unlike supervised learning (where you have labeled examples of "correct"
answers) or unsupervised learning (finding patterns in unlabeled data),
reinforcement learning is about an **agent** interacting with an
**environment** over time:

1. The agent observes the current **state** of the environment
2. It picks an **action**
3. The environment gives back a **reward** (or penalty) and a **new state**
4. Repeat, and gradually adjust behavior to get more reward over time

There's no dataset to feed it — the "data" is generated by the agent
playing the game, over and over, thousands of times.

## The two environments

**FrozenLake** — a 4x4 grid. The agent starts in a corner and needs to
reach the goal tile without stepping into a hole. Reward is `1` for
reaching the goal, `0` otherwise. There are only 16 possible positions
(states) and 4 possible moves (actions), which is small enough to use a
plain lookup table — see "Q-learning" below.

**CartPole** — a pole balanced on a cart that can move left or right.
The agent gets `+1` reward for every timestep the pole stays upright
(up to 500). The state here is 4 continuous numbers (cart position, cart
velocity, pole angle, pole angular velocity) — infinitely many possible
states, so a lookup table isn't possible. This is where we need a neural
network instead — see "DQN" below.

## Q-learning (tabular)

Q-learning keeps a table of size `[states x actions]`. Each cell holds
the agent's current estimate of "how good is this action, from this
state, accounting for future rewards too". After every move, it updates
that estimate slightly toward `reward + (best estimated value of the
next state)`. Repeated enough times across enough episodes, the table
converges toward genuinely good estimates.

The agent doesn't always pick its current best-known action — it uses
**epsilon-greedy** action selection, meaning it acts randomly some % of
the time (starting high, decaying over training) so it keeps exploring
instead of getting stuck repeating early, possibly-wrong assumptions.

## DQN (Deep Q-Network)

Same underlying idea as Q-learning, but since CartPole's state can't fit
in a table, a small neural network is trained to *predict* the Q-value
for each action given a state. Two techniques make this stable enough to
actually train:

- **Replay buffer** — past experiences are stored and trained on in
  random shuffled batches, instead of only learning from the most recent
  step (which is highly correlated with the step before it and makes
  training unstable if used directly)
- **Target network** — a slightly delayed copy of the network is used to
  compute training targets, so the target doesn't shift under the model
  every single step

## What "good" results look like

**Q-learning on FrozenLake**: success rate should climb from close to 0%
early on to 85–95%+ by the end of training. With this deterministic
(non-slippery) version of FrozenLake, the agent should eventually find
one of the actual optimal paths to the goal.

**DQN on CartPole**: average reward should climb from ~20 (barely
surviving) toward 200+ by the end of 300 episodes. It's noisy — DQN
training isn't a smooth line, expect visible ups and downs episode to
episode even while the overall trend improves. CartPole is considered
"solved" around an average of 475+ over 100 consecutive episodes, which
would need more than 300 episodes of training to reliably reach.

## Things I'd add if I kept working on this

- Save/load trained model weights instead of retraining every run
- Render a GIF of the trained agent actually playing (gymnasium supports
  this via `render_mode="rgb_array"`)
- Try a slipperier/harder FrozenLake variant to see how much worse
  tabular Q-learning does on a noisier environment
- Compare DQN against a simpler baseline (random agent, or a
  hand-written heuristic) to make the improvement more concrete
- Try Double DQN or Dueling DQN, which are common small upgrades to
  vanilla DQN that reduce overestimation bias
